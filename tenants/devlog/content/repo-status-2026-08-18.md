   _Impact: high — it's the next major deliverable. Effort: spec-only this sprint, not implementation._

2. **(Medium) Resolve the `tools` packaging fragility instead of layering another workaround on it.** `backend/pyproject.toml` already declares `tools` via `[tool.setuptools.package-dir]` and `packages.find` (added in `61f7d82`), yet `codes.py` still needed a manual `sys.path.insert` one commit later (`87b167a`) to work outside pytest (which gets `pythonpath` from `[tool.pytest.ini_options]`). Two different fixes for the same import problem is a sign the editable install isn't reliably resolving `tools` for `uvicorn`/prod invocations. Worth a real fix (verify `pip install -e ".[dev]"` actually symlinks `tools` under `site-packages`) rather than more `sys.path` patches at each new call site.
   _Impact: medium — currently masked, will resurface on the next module that imports `tools._` outside a test. Effort: small (1-2 hrs investigation).\*

3. **(Medium) Design auth before any non-localhost deployment.** Currently entirely absent (`CLAUDE.md` explicitly excludes it); fine for the current single-machine/dev-only usage, but it's a hard blocker the moment this needs to run anywhere Tom isn't the only user. Flagging now so it's a planned decision, not a scramble later.
   _Impact: high once relevant, zero today — sequence behind #1. Effort: design spike only this sprint._
