# Repository Status Brief

Act as a senior software engineer and repository analyst. Analyze the Git repository located at [repository URL or local path]. Provide a clear, structured update covering the following areas:

Latest Changes: Summarize the most recent commits (from [start date/branch] to [end date/branch], or the last [number] commits). Highlight key features, bug fixes, refactors, and any breaking changes.

Documentation Changes: Identify any updates to README, API docs, architecture docs, or inline comments. Note if documentation is missing, outdated, or inconsistent with the code changes.

Next Sprint Suggestions: Based on the current codebase state, open issues, and recent trends, recommend 3–5 actionable tasks for the next sprint. Prioritize them by impact and effort, and briefly justify each recommendation.

Risks & Concerns: Flag any code quality issues, technical debt, merge conflicts, or failing tests you notice.

Output format: Use markdown with clear headings. Keep the executive summary under 150 words. For the sprint suggestions, use a numbered list with priority tags (High/Medium/Low). If you find any critical issues, place them in a callout box at the top.

Be specific: reference commit hashes, file names, and line numbers where relevant. Avoid generic advice. If certain data is unavailable, state the assumption or gap explicitly.
